PERSISTENT NATIVE COMPUTATIONAL COPY
==================================
Source: DM_persistent.cpp, generated by build_native.R from the immutable
dm_adaptive_tempering/DM_tempered.cpp. Baseline copies and private headers are
byte-identical to their original versions. The generator stores reference/native
MD5 values and extraction provenance in native_generation.rds.

The new source retains the complete prefix of original numerical helper/audit
exports. Its statistical sweep is copied verbatim except the dead native
burn-in adaptation branch and dead post-run diagnostics accumulation. The
current PT wrapper always invokes the original with burn=0/adapt_g=false and
performs temperature/diversity adaptation in R, so those branches do not affect
transitions. The schedule, R adaptation and RNG remain outside this API.

CREATE (no RNG, optimizer or sampler):
ctx <- module$apt_context_create(X,Y,neighbors,method)
Supported methods: online_similarity_local,online_similarity_flip,uniform_flip.

STEP (one bounded native MCMC sweep):
v <- module$apt_context_step(ctx,physical,g,Sigma_alpha,inverse_temperature,
                             coefficient_optimizer_maxit=25,
                             score_optimizer_maxit=1,joint_scale=2)
Sigma_alpha must ALREADY include the old apt_args deterministic temperature
factor min(1/inverse_temperature,100). It is not multiplied again by C++.
The context uses the exact current fixed production settings for priors,
discrete proposal family and beta-only mixture. It is not a general replacement
for all arguments of DM_tempered_VS_RJMCMC.

The compact return supplies physical,ll,lp,effective,counts and local_seconds,
plus nonfinite_mh_ratios_rejected,optimizer_zero_fallbacks and component priors.
counts is a named double vector alpha,flip,local,joint,projections. lp uses
long-double sums for the beta/indicator priors; component prior values are also
returned so the wrapper may reproduce the original R sum expression exactly.
No fitted score is returned initially:reuse the same apt_score R function for
the first numerical/RNG equivalence comparison.

CONTEXT INFO (no RNG, optimizer or sampler):
module$apt_context_info(ctx)

What persists:immutable X/Y,validated undirected sorted neighbor graph,row
totals,uniform proposal matrix,and reusable selected-design/physical-view
storage. Context lifetime is a worker lifetime. Sharing a worker context among
replicas is safe because every step receives and rebases the entire physical
state,including exchanged states.

What is deliberately rebased every sweep:alpha/xi/beta,selected designs,Xbeta,
eta,gamma,priors,penalties and per-call beta_hat_memory. This preserves the old
one-sweep initialization arithmetic. Exact static fit/context caches retain
their original full-condition key semantics. The full end-of-sweep likelihood
refresh is retained to preserve numerical-drift behavior.

Numeric diagnostic counters reset on each invocation and are returned per
sweep,not accumulated through the native context.

RDS/restart:serialize physical/tuning/RNG and adaptation in R as before. Native
external pointers must be recreated from the immutable data after restart;
they are not serialized sampler state and must not be reused after RDS.
Step/info entry points reject wrong-type,wrong-tag and NULL/unserialized pointers
with an R error before dereferencing them.

This implementation was generated and statically inspected by the native
builder. Compilation,seeded comparisons,parallel/restart verification and
timing measurements are performed by the parent orchestration workflow.
No production run is authorized or launched by this file.
